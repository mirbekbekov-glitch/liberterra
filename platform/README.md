# Исходники действующей Liberterra

Эта база подготовлена для дальнейшей разработки CRM из кода, сверенного с production 27 октября 2026 года. Это фиксация текущей платформы, а не завершённая модернизация Liberterra 3.0. Секреты, рабочие таблицы, сессии, документы клиентов и каталог загруженных фотографий в репозиторий не включены.

## Текущая архитектура

Frontend Worker содержит встроенные публичные HTML/CSS/JS. Backend Worker обслуживает защищённые операции, каталог и CRM, использует `ASSETS` и D1, а операции с приватной CRM передаёт Apps Script. В Apps Script проверяются учётная запись, статус агента и права на записи; данные хранятся в приватной книге Sheets. Имена требуемых Cloudflare-привязок записаны в манифесте.

Файлы `public/api/crm-workflow/` соответствуют реальным URL `/api/crm-workflow/*`. Одноимённые адреса в корне сайта могут возвращать 404: это нельзя трактовать как отсутствие рабочего CRM без проверки ссылок в действующей HTML-странице. При сверке также обнаружена ссылка на `/market-valuation.js`, возвращающая 404; это оставлено как наблюдение текущего состояния, без исправления production.

Worker-файлы включены в опубликованном виде, со встроенными ресурсами. Изменение отдельного файла `public/` само по себе не пересобирает эти ресурсы. Первый этап последующей разработки — выделить воспроизводимую сборку ресурсов и доказать, что её результат сохраняет маршруты, привязки и поведение. Параллельные локальные `worker.js` и `google_sheets_webhook.gs` из прежнего снимка не используются как подтверждённая production-база.

## Локальная проверка без зависимостей

Из корня репозитория, Node.js 24:

```powershell
node platform/scripts/verify-source.cjs --baseline
node platform/tests/crm-workflow.test.cjs
node platform/tests/crm-gateway.test.cjs
```

`--baseline` проверяет неизменность первоначального снимка. После намеренных правок используйте проверку без этого флага и анализируйте изменения относительно исходного манифеста. Проверка синтаксиса не выполняет опубликованные Worker-бандлы и не вызывает production API.

Тесты проверяют сохранение в тестовом хранилище, версии, повтор мутации, ограничение действий и размера запроса, подмену идентификатора, отказ другому агенту, публичную проекцию подборки, её отзыв и связь задач с клиентом. Они не доказывают прохождение авторизованных пользовательских сценариев в production. Новые реальные записи во время этой сверки не создавались.

## Границы выпуска

В ветке отсутствуют активная конфигурация автоматического развёртывания и значения секретов. Перед выпуском потребуется отдельное тестовое окружение с приватной тестовой книгой, изоляцией двух агентов и проверкой сохранения после перезагрузки. Полный облачный набор ASSETS, D1/Sheets, настройки доступа Google Drive, пользовательские фотографии и документы не являются частью этого снимка. Публичные файлы здесь — проверенный набор ресурсов сайта, а не экспорт всего хранилища.

Состояние на момент подготовки: production `/health` вернул `ok: true`, `checked: 5`, `failures: []`. Ветка предназначена для разработки и ревью. Создание коммита или PR не означает выпуск на сайт.
