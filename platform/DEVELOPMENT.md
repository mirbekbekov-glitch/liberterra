# CRM: сборка и изолированный стенд

Рабочая ветка: `crm/production-baseline-20261027`. Команды выполняются из корня репозитория с Node.js 24.20.0. Установка пакетов, ключи и доступ к интернету не нужны.

```powershell
node platform/scripts/build.cjs
node platform/scripts/verify-source.cjs
node --test platform/tests/*.test.cjs
node platform/dev/server.cjs
```

Откройте `http://127.0.0.1:4173/`, выберите «Агент A». Создайте клиента, затем сделку. Второй агент имеет отдельные записи, «Без допуска» получает отказ. Остановка сервера: Ctrl+C. Другой порт: `node platform/dev/server.cjs 4174`.

## Исходники и воспроизводимость

- `workers/` — неизменяемые шаблоны опубликованных Worker. Их SHA-256 проверяется перед каждой сборкой. Рабочие результаты находятся в `dist/workers/`.
- `assets/` — 105 файлов, извлечённых из трёх встроенных карт ресурсов. `assets.json` фиксирует происхождение и первоначальные хеши. Одноразовый `extract-assets.cjs` уже выполнен и отказывается перезаписывать манифест.
- CRM UI редактируется в `assets/backend/crmWorkflowAssets/`. Новая воронка и рабочий день находятся в `features/deals.js` и `features/deals.css`; `features.json` подключает их к существующим ресурсам, без новых production-маршрутов.
- `apps-script/` — серверные исходники, копируемые в результат. `public/` и `provenance.json` остаются первоначальным HTTP-снимком.
- `dist/build-manifest.json` содержит хеши выходных файлов без даты, случайных ID и абсолютных путей. Две чистые сборки и повторная сборка проверяются автоматическим тестом. Не кладите ручные файлы в `dist`: неизвестные файлы останавливают повторную сборку.

До изменений UI извлечение и обратная сборка воспроизвели оба исходных Worker побайтно. Теперь backend отличается намеренно; site Worker сохраняет SHA-256 `81cbf7f6eed3daa1f2ea47c3962255e9f0c7fbe1de57a143ee7912715a6918ee`. Исходные Worker и публичный снимок не изменены. `verify-source --baseline` предназначен для исходного коммита, а не для изменённого Apps Script.

## Изоляция

Стенд слушает только loopback. HTTP Host и Origin проверяются. Browser CSP разрешает подключения только к этому origin. API не проксируется на рабочий сайт; неизвестные действия недоступны. Сервер исполняет настоящий CRM gateway и Apps Script workflow в VM с синтетическими идентификаторами, каталогом и адаптером Sheets; внешние запросы адаптера запрещены. Это тестовая замена авторизации и инфраструктуры, не проверка настоящих Telegram/email-сессий, Google Sheets или Cloudflare bindings. Остальные разделы платформы здесь не эмулируются полностью.

Фикстуры двух агентов и нескольких объектов явно тестовые. CRM-записи хранятся в `platform/.sandbox/sheets.json` (игнорируется Git). Одновременный запуск с тем же каталогом блокируется `server.lock`. После аварийного завершения убедитесь, что прежний процесс остановлен, прежде чем удалять оставшийся lock. Для нового набора данных при остановленном сервере переименуйте `.sandbox`, сохранив старый набор как резервную копию. Не вводите настоящие персональные данные в стенд.

## Первое улучшение CRM

«Рабочий день» показывает активные сделки, финальные этапы, задачи на сегодня и просрочки по времени Бишкека. Плановые комиссии суммируются раздельно по USD/KGS и не считаются полученным доходом. До загрузки задач отображается неизвестное состояние, а не ложный ноль.

«Сделки» — отдельные записи `kind=deal`, связанные с собственным клиентом и доступным объектом. Десять этапов: новый лид, квалификация, подбор, назначен показ, показ проведён, переговоры, согласование, документы, успешно закрыта, проиграна. Разрешены соседний следующий/предыдущий этап и потеря; успешное закрытие — из документов. Успех требует объекта и положительной суммы, потеря — причины. Терминальные этапы нельзя переоткрывать; остальные поля редактируются. На широком экране доступно перетаскивание, на телефоне — выбор этапа и форма. Переходы всегда проверяет сервер.

Сохранены проверки роли/владельца, блокировка, версия и idempotency. История фиксирует автора, серверное время, переход и имена изменённых полей. Она ограничена 100 событиями и размером записи 45 000 символов: превышение отклоняет запись, не стирая историю. Отдельный долговременный журнал и управляемое переоткрытие сделок — следующие этапы разработки. История не хранит предыдущие значения всех полей и не является финансовым аудитом.

## Выпуск и откат

Развёртывания в этом изменении нет. До будущего выпуска нужна проверка в отдельном облачном окружении с тестовой приватной книгой, реальной авторизацией двух агентов и Cloudflare-привязками. Локальный стенд этого не заменяет. Для выпуска потребуется отдельное разрешение пользователя.

Изменение хранения добавочное: новый тип в существующем листе CRM Workflow, без удаления или преобразования записей клиентов. Сначала обновляется Apps Script с поддержкой `deal_stages` и `deal`, затем собранный backend Worker. Старый сервер не должен получать новую форму: UI без метаданных этапов блокирует создание сделки. При откате сохраняются все строки сделок; нельзя очищать лист. Старый интерфейс не показывает новый тип, поэтому перед откатом нужен экспорт и план сохранения доступа к этим данным.

## Проверки 2026-10-27

Автоматически: исходные workflow/gateway, переходы и оба исхода сделки, история и её предел, версии, повтор мутации, доступ двух агентов, связанные записи, точность денег, детерминированная сборка, HTTP Origin/гость/неодобренный агент, запрещённый API и восстановление после перезапуска.

В браузере локального стенда: создание клиента и сделки, сохранение суммы/комиссии/следующего действия, переход к квалификации и история, перезагрузка, показатели обзора, отсутствие сделки у агента B; воронка и форма на ширине 360 px. Все введённые данные синтетические. Проверка не подтверждает production-развёртывание.
