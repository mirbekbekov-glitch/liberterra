## Platform

web

## Users

- **Основной пользователь — клиент, ищущий жильё в Бишкеке и Кыргызстане.** Снимает или покупает квартиру, дом, коммерцию или участок. Часто с телефона, часто внутри Telegram. Задача: за несколько минут понять, какие объекты реально существуют и свободны сейчас, и выйти на агента по конкретному объекту. При конфликте интересов решение принимается в пользу клиента.
- **Агент по недвижимости.** Аккредитованный агент Liberterra: ведёт клиентов, объекты, сделки и задачи в кабинете (`/agent-cabinet.html`), размещает объекты, подтверждает их актуальность, отвечает на заявки. Публичный каталог для него — источник обращений.
- **Собственник объекта.** Размещает объект через `/add-object.html`; дальше объект попадает в тот же поток проверки.

## Product Purpose

Каталог проверенных объектов недвижимости Кыргызстана и рабочее место агента в одной системе. Клиент видит объекты с реальными фотографиями, ценой в сомах или долларах, районом и отметкой проверки; если подходящего объекта нет — оставляет заявку, и её видят агенты. Успех: клиент дошёл до разговора с агентом по объекту, который действительно доступен.

## Positioning

**CRM и телефония для агента — это и есть механизм актуальности каталога.** Объявления не заливаются произвольными пользователями: их ведут агенты, которые в этой же системе работают с клиентами, сделками и звонками. Отметка «Проверен» и дата актуальности — побочный продукт реальной работы агента, а не самодекларация подателя объявления. Агрегатор объявлений не может честно повторить это, не построив рабочее место агента.

## Operating Context

- **Боевой сайт:** `liberterra.kg` на Cloudflare (Worker + Pages). Оттуда же отдаются остальные страницы и API.
- **GitHub Pages:** workflow `.github/workflows/deploy.yml` публикует этот репозиторий как есть при push в `main`. Это превью-режим; `index.html` должен оставаться работоспособным в обоих режимах.
- **Данные:** `GET /api/public-catalog` (CSV, колонки включают `id, deal, status, title, city, district, area, floor, photo_url, tg_link`), `GET /api/exchange-rate` (курс сом/$). Фотографии — с Worker `…workers.dev/uploads/`.
- **Соседние страницы вне этого репозитория:** `/object.html`, `/requests.html`, `/agents.html`, `/agent-cabinet.html`, `/add-object.html`, `/add-request.html`, вход `/api/crm-workflow/login.html`. Их исходники живут в снимке Worker/бота (см. `README_GITHUB.md`), не здесь.
- **Telegram:** бот `@Liberterra_kg_bot` и Mini App — отдельный канал к тому же каталогу.
- **Сцена использования:** телефон, мобильный интернет, 360–414 px — первичный размер проверки; широкий экран — вторичный.
- **Партнёры, указанные на сайте:** ololo, Cleaner.kg, Arabel, mel.

## Capabilities and Constraints

- `index.html` — один самодостаточный файл: инлайновые `<style>` и `<script>`, без сборки и пакетного менеджера.
- Внешние зависимости: Google Fonts (Onest; Manrope загружается, но в CSS не используется), Leaflet 1.9.4 и markercluster 1.5.3 с cdnjs, плюс скрипт `/listing-format.js`, который отдаёт Worker, — в репозитории его нет.
- Маршрутизация: hash (`#/`, `#/catalog`) внутри `index.html`; остальные разделы — обычные URL соседних страниц.
- Виды каталога: плитка и карта Leaflet. Координаты берутся из таблицы центров районов (`DISTRICT_COORDS`) — это приблизительная привязка по району, а не геокодирование адреса.
- Валюта переключается сом/$, курс приходит из API; при недоступности API показывается состояние ошибки с кнопкой «Повторить».
- Любой текст из каталога экранируется через `esc()` перед вставкой в шаблон.
- Роль и доступ к CRM проверяются на сервере через сессию; в клиентском коде секретов и реальных персональных данных быть не должно.
- UI только на русском. Киргизский и английский в планах, сроки не подтверждены.
- **Открытые вопросы, которые нельзя додумывать:** `CLAUDE.md` и `README.md` описывают прежнюю демо-версию (вымышленные данные, `CONFIG`, переключатель ролей) и расходятся с кодом — авторитет у кода; что именно из этих документов ещё верно, не подтверждено. Не подтверждено и поведение `index.html` в режиме GitHub Pages, где `/api/*` и `/listing-format.js` недоступны.

## Evidence on Hand

- Реальные фотографии объектов приходят из каталога (`photo_url`); карточка без фото честно пишет «Фото уточняется».
- Реальные API: `/api/public-catalog`, `/api/exchange-rate`.
- Названия партнёров на сайте: ololo, Cleaner.kg, Arabel, mel.
- **Чего нет и что нельзя выдумывать:** отзывы, кейсы, число объектов, число агентов, объём сделок, пресса, сертификаты, рейтинги агентов. В прежней демо-версии рейтинги и сертификаты агентов были вымышленными; подтверждённых данных на их месте сейчас нет.

## Product Principles

1. **Актуальность важнее объёма.** Лучше меньше объектов, но тех, что существуют и свободны сегодня, с видимой датой проверки.
2. **Клиент выигрывает конфликт.** Интересы агента и агентства не ставятся выше ясности для ищущего жильё.
3. **Телефон — первый экран.** Если на 360 px неудобно, задача не закрыта.
4. **Не обещать того, чего нет.** Отметки, даты, цифры и фотографии показываются только там, где за ними есть реальные данные; пустое состояние честнее заглушки.
5. **Путь до агента короткий.** С любой карточки и любого пустого результата видно следующее действие: объект, заявка или кабинет.

## Accessibility & Inclusion

Формального обязательства по стандарту не зафиксировано. В коде есть ссылка «К содержимому», `aria-live` на результатах, видимый фокус (`:focus-visible`), цели нажатия 44 px. При этом детектор Impeccable находит нарушения контраста WCAG AA: `#8A8A8A` на `#F5F6F8` — 3.2:1, `#979798` на `#F5F6F8` — 2.7:1, `#8A8A8A` на `#FFFFFF` — 3.5:1 при норме 4.5:1. Целевой уровень — решение, которое ещё не принято.
