# Liberterra — CRM агента

## Принцип
Каждый агент видит и меняет только свои данные. Изоляция обеспечивается на сервере (в Postgres — Row Level Security по `agent_id`), а не скрытием кнопок в интерфейсе. Нынешний переключатель роли в браузере — только демо.

## Сущности (минимум)
- `agents` — профиль, статус (`draft|pending|approved|rejected|blocked`), telegram_id, телефон.
- `clients` — имя, телефоны, Telegram, источник, потребность (аренда/покупка, бюджет, районы), статус воронки, `agent_id`.
- `listings` — объект, `agent_id`, статус (`on_review|published|archived`), «договор подписан», `actual_at`, lat/lng.
- `deals` — клиент + объект + этап (`new → contact → viewing → deposit → closed|lost`), сумма, комиссия.
- `tasks` — что сделать, срок, связь с клиентом/объектом/сделкой (питает блок «Что сделать сегодня»).
- `activities` — единая лента: заметки, звонки, сообщения, просмотры. Звонки подробно в скилле `liberterra-calls`.
- `viewings` — запись на осмотр.

## Экраны кабинета
Сегодня (задачи, просроченная актуальность, новые заявки) → Клиенты → Объекты → Сделки (канбан) → Звонки → Профиль. Карточка клиента показывает всю ленту активности и ближайшую задачу.

## Правила
- Правило актуальности: объект без подтверждения N дней помечается и попадает в задачи агента.
- Комиссия: доля закрывающего агента из `CONFIG.commissionAgentPct`; итог рассчитывается после сделки.
- Дубликаты клиентов: проверять по нормализованному телефону (+996…).
- Удаление мягкое (`deleted_at`), история изменений пишется в аудит.
- Экспорт клиентов в CSV только для самого агента.
- Персональные данные клиентов — минимум, шифрование на хранении, доступ логируется.
- Если решено использовать Bitrix24 вместо своей CRM, сайт интегрируется с ним через вебхуки и REST API, а эта схема остаётся ориентиром по полям.
